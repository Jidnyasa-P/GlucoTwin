# Data dictionary and provenance

## Data included in this repository

| File | Contents | Provenance | Intended use |
|---|---|---|---|
| `sample_synthetic/patient_profile.csv` | One fictional profile with age, diabetes type/duration, HbA1c, and a medication-history placeholder | Synthetic, generated for demonstration | Dashboard/state context only; not model input |
| `sample_synthetic/glucose_observations.csv` | 288 glucose values at five-minute intervals for `SYNTH-001` | Synthetic, generated by `src/glucotwin/data.py` with fixed seed | UI demo and state updates, not clinical evaluation |

## Synthetic generation

The generator creates a baseline, smooth periodic variation, Gaussian meal-like pulses, random walk drift, and random noise. It is an engineering fixture, **not a physiological simulator**. Generated readings are in mg/dL and timestamps are UTC ISO timestamps. Five-minute cadence is the intended cadence; the quality checker flags gaps greater than ten minutes. Values are clipped to 55–280 mg/dL in the generator.

The sample is reproducible: `python scripts/generate_synthetic_data.py`. The profile's provenance and each observation's `provenance` field explicitly identify synthetic records.

## External data investigated; not bundled

- **DiaTrend** paper and data landing reference: https://www.nature.com/articles/s41597-023-02469-5 . The paper describes longitudinal CGM and insulin-pump data. The paper is open access under CC BY 4.0, but that does not automatically establish the licensing terms for every data file or third-party component. Verify the actual repository/host terms and access requirements before using or redistributing any data. No DiaTrend records are included or evaluated by this version.
- **Synthea**: https://github.com/synthetichealth/synthea . Generates synthetic health records; useful for EHR-format demonstrations but not a validated physiological simulator. This version uses a small hand-defined fictional profile rather than Synthea exports.

## Training and evaluation boundaries

`python scripts/evaluate.py` creates a fresh, fixed-seed synthetic cohort. Eighteen synthetic patient IDs are used for training and six different IDs for held-out testing. Windows are constructed independently within each patient, and no patient ID appears in both partitions. The primary target is the glucose value 30 minutes after the last input observation, using 12 preceding five-minute readings. The benchmark compares persistence with a HistGradientBoostingRegressor on the exact same held-out windows.

The generated patients share the same synthetic generator family. Patient-separated splitting avoids direct patient overlap but is not a substitute for external validation. No real CGM or EHR data was downloaded. EHR context is not used as a forecasting feature; the README and dashboard explicitly disclose this distinction.
